# 테스트 서버 색인 캡처 — 실행 절차서 (차하나 PD용)

**목적** Stripe 악용 사고에서 "테스트 서버가 구글에 노출된 것이 공격 경로였는지"를 **추측 없이** 판단할 근거를 남깁니다.
**대상** 테스트 서버(스테이징) 도메인 — 대표님/개발팀에 주소 확인 필요
**기한** 차단 작업 **전에** 완료 (차단·`noindex` 를 먼저 하면 색인 기록이 사라집니다)

> 이 문서는 **캡처만** 다룹니다. 해석("그래서 공격자가 찾았나?")은 개발·대표가 로그와 함께 판단합니다.
> 캡처한 화면에는 **URL·날짜·시각이 보이게** 해야 증거로 쓸 수 있습니다.

---

## 0. 먼저 확인할 것 (5분)

| 확인 | 방법 | 결과 적기 |
|---|---|---|
| 테스트 서버 주소 | 대표님·전유준 개발자에게 문의 | `____________________` |
| 그 주소가 구글에 색인됐는가 | 아래 2장 | 예 / 아니오 |
| 서치콘솔 속성에 그 주소가 등록돼 있는가 | 아래 3장 | 예 / 아니오 |
| 내 계정에 서치콘솔 권한이 있는가 | 11/10 대표님이 팀원 추가 예정 | 예 / 아니오 |

**권한이 없을 때:** 대표님께 아래 3가지를 부탁드리세요. (그대로 복사해서 보내시면 됩니다)

> 대표님, 테스트 서버 색인 증거를 남기려고 합니다. ① 서치콘솔에서 테스트 서버 속성의 **색인 현황 캡처** ② 구글에서 `site:테스트서버주소` 검색 결과 **캡처** ③ 가능하면 **페이지 색인 생성 보고서의 최초 색인일** 캡처를 부탁드립니다. 화면에 주소와 날짜가 보이게 부탁드립니다. 차단은 이 캡처를 받은 뒤에 진행하겠습니다.

---

## 1. 캡처 전 공통 준비 (한 번만)

1. **시계 확인** — 작업대(PC) 우측 하단 시간이 실제와 맞는지 확인. 화면 캡처에 시각이 같이 찍혀야 합니다.
2. **브라우저 시크릿 창** 사용 — 내 검색 이력·로그인 상태가 결과에 영향을 주지 않게.
3. **창 크기** — 결과가 잘리지 않게 브라우저를 최대화. 목록이 길면 **스크롤하며 2~3장**으로 나눠 찍습니다.
4. **주소창이 보이게** 찍기 — 증거의 핵심입니다. 주소창을 숨기는 캡처 도구는 쓰지 마세요.
5. **파일 이름 규칙** (아래 4장) 을 미리 정해 두고 저장합니다.

**캡처 방법(윈도우):** `Win + Shift + S` → 영역 선택 → 알림의 이미지를 클릭 → `Ctrl + S` 로 저장
**캡처 방법(맥):** `Shift + Command + 4` → 영역 선택 → 바탕화면에 저장

## 2. 구글 검색 결과 캡처 (`site:` 검색) — 가장 중요

### 2-1. 검색

1. 시크릿 창에서 `google.com` 접속
2. 검색창에 아래를 입력 (주소는 실제 테스트 서버 주소로)

```
site:test.xconda.ai
```

> `site:` 뒤에 `https://` 나 `/` 는 붙이지 않습니다. 하위 경로까지 보고 싶으면 `site:test.xconda.ai ai` 처럼 단어를 덧붙입니다.

### 2-2. 결과별로 찍을 것

| 결과 | 판정 | 다음 행동 |
|---|---|---|
| 결과가 **1건 이상** 나옴 | 🔴 **색인됨** — 증거 확보 필수 | 2-3 캡처 |
| "검색결과가 없습니다" | 🟢 색인 안 됨 | **그 화면도 캡처**(증거) |
| "일치하는 항목이 없습니다" + 유사 결과 | 🟡 부분 색인 가능 | 그대로 캡처 + 3장 확인 |

### 2-3. 찍어야 하는 화면 (3장)

1. **검색 결과 전체** — 검색어·결과 개수("약 N개")·URL이 보이게
2. **결과 페이지 2~3장** — 스크롤해서 색인된 하위 주소 목록
3. **결과가 0건일 때** — "검색결과가 없습니다" 문구와 검색어가 함께

**주의:** 구글 결과는 사람마다 다를 수 있습니다. **"내 화면에서 이렇게 나왔다"** 를 남기는 것이 목적이므로, 나온 그대로 찍으면 됩니다. 다른 사람 화면과 다르다는 이유로 다시 찍을 필요는 없습니다.

## 3. 서치콘솔 색인 현황 캡처

### 3-1. 들어가는 곳

1. `search.google.com/search-console` 접속 (권한 있는 계정)
2. 상단 **속성 선택**에서 **테스트 서버 주소** 선택
   - 목록에 없으면 → **속성이 등록되지 않은 것**입니다. 그 사실 자체를 캡처(속성 목록 화면)하고, 2장(`site:` 검색) 결과로 대신합니다.
3. 왼쪽 메뉴 **색인 > 페이지** 클릭

### 3-2. 찍을 화면 (4장)

| 순서 | 화면 | 왜 필요한가 |
|---|---|---|
| 1 | **페이지 색인 생성** 요약 — "색인됨 / 색인되지 않음" 숫자 | 규모 파악 |
| 2 | **색인됨** 탭의 URL 목록 | 어떤 페이지가 노출됐는지 |
| 3 | URL 1건 클릭 → **"URL 검사"** 결과 (페이지 색인 생성: **"URL이 Google에 등록되어 있음"**) | 개별 증거 |
| 4 | 해당 URL의 **"최초로 색인된 날짜"** (URL 검사 화면 또는 페이지 색인 생성 보고서) | **언제부터 노출됐는지 = 사고와의 인과 판단 근거** |

> **3-3. `robots.txt` 신고 화면 (있으면 함께)**
> 서치콘솔 왼쪽 **설정 > robots.txt** 에서 테스트 서버의 robots.txt 가 "가져오기 성공"인지, `Disallow` 가 있는지 캡처합니다. 테스트 서버 robots.txt 주소를 직접 열어(`테스트서버주소/robots.txt`) 화면 캡처해도 됩니다.

> **3-4. 사이트맵 제출 이력 (있으면)**
> 왼쪽 **색인 > 사이트맵** 화면 — 테스트 서버 사이트맵이 제출됐다면 "성공" 상태와 제출일이 증거가 됩니다.

## 4. 파일 저장 규칙 (증거 무결성)

**저장 위치:** 사고 증거 폴더 (예: Drive `XCONDA_사고증거_20261107/03_SEO_테스트서버색인/`)

**파일 이름:** `YYYYMMDD-HHMM_수집자_화면내용.png`

```
20261108-1130_차하나_SC_site검색결과.png
20261108-1132_차하나_SC_페이지색인요약.png
20261108-1134_차하나_SC_색인된URL목록.png
20261108-1136_차하나_SC_URL검사_최초색인일.png
20261108-1138_차하나_SC_robots.txt.png
```

**같이 남길 기록** (표 하나로 충분합니다)

| 파일명 | 캡처 시각 | 캡처한 화면 | URL·검색어 | 비고(0건/색인됨 등) |
|---|---|---|---|---|
| 예: 20261108-1130_차하나_SC_site검색결과.png | 2026-11-08 11:30 KST | 구글 `site:` 결과 | `site:test.xconda.ai` | 색인 3건 확인 |

**해시 남기기(권장·선택):** 파일이 변조되지 않았다는 증거입니다.
- 윈도우: PowerShell 에서 `Get-FileHash 파일명 -Algorithm SHA256`
- 맥: 터미널에서 `shasum -a 256 파일명`
- 결과를 위 표 옆에 붙여 넣거나 `해시.txt` 로 같은 폴더에 저장

> 캡처 원본은 **자르거나 편집하지 마세요.** 일부만 필요하면 사본을 만들어 표시하고, 원본은 그대로 둡니다.

---

## 5. 캡처 후 (차단 전 마지막 확인)

- [ ] `site:` 검색 결과 캡처 완료 (0건이어도 캡처)
- [ ] 서치콘솔 페이지 색인 현황 캡처 완료 (속성 없으면 속성 목록 캡처)
- [ ] 색인된 URL 이 있으면 **최초 색인일** 캡처 완료
- [ ] 파일명 규칙대로 저장 + 캡처 기록표 작성
- [ ] 원본 편집 없음 확인
- [ ] **전유준 개발자에게 "캡처 끝났으니 차단 진행해도 됩니다" 전달** ← 이 순서를 꼭 지켜 주세요

## 6. 자주 막히는 곳

| 증상 | 해결 |
|---|---|
| 서치콘솔에 테스트 서버 속성이 없음 | 속성 목록 화면을 캡처하고, `site:` 검색 결과로 대신. 대표님께 "속성 미등록" 사실 보고 |
| `site:` 검색에서 결과가 0건인데 걱정됨 | **0건도 증거입니다.** 화면을 찍고 넘어갑니다 |
| 색인은 됐는데 최초 색인일이 안 보임 | URL 검사 화면 상단의 "페이지 색인 생성" 문구와 날짜를 찍고, 안 보이면 "확인 불가"로 기록 |
| 구글 결과가 회사 동료와 다름 | 정상입니다. **내 화면 기준**으로 그대로 캡처. 필요하면 동료 화면도 각자 이름으로 보관 |
| 캡처에 주소창이 안 나옴 | 도구 설정에서 "창/화면 전체" 캡처로 바꿔 다시 |
| 권한이 없어 3장을 못 함 | 2장(`site:`)만 먼저 하고, 대표님 캡처를 받아 합칩니다. **차단은 그 뒤에** |

## 7. 이 캡처로 알 수 있는 것 / 없는 것

| 알 수 있는 것 | 알 수 없는 것 |
|---|---|
| 테스트 서버가 구글에 색인됐는지 여부 | 공격자가 **실제로** 검색해서 들어왔는지 (접속 로그 필요) |
| 색인된 URL 범위와 **최초 색인일** | 색인일과 사고 발생일의 인과관계 (개발·대표 판단) |
| robots.txt·사이트맵 제출 상태 | 테스트 서버 자격증명이 유출됐는지 (코드·로그 확인 필요) |

> 그래서 이 캡처는 **"가능성"을 좁히는 자료**입니다. 단정하지 말고 "색인은 11/00부터였고, 사고는 11/06이다" 처럼 **사실만** 보고해 주세요. 판단은 개발·대표가 로그와 함께 합니다.
