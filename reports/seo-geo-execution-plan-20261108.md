## 3. 저장소와 대조해 **사실이 달라진 것** (계획서 수정 필요)

### 3-1. "시나리오 한 편이 완성 영상이 되기까지" 두 주소 문제 → **이미 정리 완료**

|---|---|
| 살아 있는 주소 | `post/scenario-to-final-video/` (사이트맵·en·ja·zh 포함) |
| 옛 주소 | `post/xconda-production-map/` → canonical + `noindex` + 0초 리다이렉트로 새 주소 지정 |
| 처리 시점 | 2026-11-02 중복 글 통합(`REDIRECTS` 에 등록) |

→ **11/14 항목에서 빼고 완료 처리**하세요. 같은 자리에 실제 문제인 "주소 없는 News 2건"을 넣는 것이 맞습니다.

### 3-2. "오타"는 1곳이 아니라 **3곳**, 그리고 SEO 칸은 이미 정상

| 위치 | 현재 값 | 조치 |
|---|---|---|
| `Title` (제목) | 클라우드 오퍼스 5.5와 블렌더로 게임 3D 모델 만드는 8단계 방법 | "클로드"로 수정 |
| `Summary` (카드 요약) | 클라우드 오퍼스 5.5와 블렌더를 연결해… | "클로드"로 수정 |
| 본문 첫 항목 | 클라우드 오퍼스 5.5가 파이썬 코드를 작성하고… | "클로드"로 수정 |
| `SEO 제목` | 오퍼스 5.5와 블렌더로 … (정상) | 그대로 |
| `SEO 설명` | 클로드 오퍼스 5.5를 블렌더 MCP로 … (정상) | 그대로 |

→ **SEO 칸은 이미 "클로드"로 되어 있습니다.** 제목·요약만 고치면 검색 결과·카드에서 바로 반영됩니다.

### 3-3. "미게시 글 3개를 개발에 전달" → **초안은 0건**

스냅샷 기준 게시 114건 / 초안 0건입니다. 실제로 개발 확인이 필요한 것은 **초안이 아니라 주소·커버 누락**입니다(→ `reports/content-audit-20261108.md`).

- 주소 없음 **2건** (News 2건, Slug 미입력)
- 커버 누락 **9건** (본문 글 기준, Q&A 73건은 구조상 제외)

## 4. 이번 사고와 연결해 **순서를 바꿔야 할 것**

### 4-1. (신규·최우선) Notion 동기화가 멈춰 있습니다 — 발행 작업의 선행 조건

11/07 21:25Z부터 `Notion 스냅샷 생성` 단계가 **51회 연속 실패**했고, 사이트는 11/07 22:08Z 스냅샷에 멈춰 있습니다. 즉 **지금 체크리스트를 운영해도 결과가 사이트에 나타나지 않습니다.**

- 조치(이번 작업에 포함): 실패 시 ① 실행 요약에 "사이트는 직전 스냅샷" 명시 ② `::warning::` ③ 실패하면 게시·커밋을 **건너뛰도록** 워크플로 수정
- 확인 순서: `NOTION_TOKEN` → `NOTION_DATABASE_ID`/`PAGE_ID` → 연동 권한 → 노션 일시 오류
- **차하나 PD 체크리스트 0번**으로 추가 권장: "동기화 배지가 6시간 이상 지연이면 발행 점검 중단하고 개발에 알림"

### 4-2. "테스트 서버 차단"은 11/20이 아니라 **보안 수정 일정(48시간)** 으로

원 계획의 판단(공격 경로 가능성)에 동의합니다. 다만 **차단이 증거를 지울 수 있으므로 순서가 중요합니다.**

| 순서 | 할 일 | 담당 | 시점 |
|---|---|---|---|
| 1 | Search Console → 색인 → 페이지에서 **테스트 서버 색인 URL·최초 색인일 캡처** | 대표(권한 이전 전) | 차단 **전** |
| 2 | Google `site:테스트서버주소` 검색 결과 **전체 화면 캡처**(날짜 표시) | 대표 | 차단 **전** |
| 3 | 캡처를 사고 증거 폴더에 보관 + 수집 일시·수집자 기록 | 차하나 PD | 즉시 |
| 4 | 접근 차단(IP 제한/VPN)·인증 추가, `noindex` 병행 | 개발 | 48시간 내 |
| 5 | 차단 후에도 캡처·기록은 **삭제하지 않음** | 전원 | 상시 |

> 핵심은 **"언제부터 색인됐는가"** 입니다. Stripe 사고(11/06) **이전** 색인이라면 검색으로 테스트 서버를 찾았을 가능성을 배제할 수 없고, **이후**라면 그 연결은 약해집니다. 어느 쪽이든 **캡처한 시각 자체가 증거**이므로, 해석은 개발·대표가 로그와 함께 판단해야 합니다.

**이 저장소에서 확인한 범위(참고):** 테스트 서버 주소·설정은 이 저장소에 없습니다. `dev.html` 은 `noindex, nofollow`, `dist-test/` 는 `.gitignore` 로 배포 대상이 아닙니다. 따라서 테스트 서버 실체 확인은 개발 담당 몫입니다 — **제가 "노출됐다/안 됐다"를 단정하지 않습니다.**
