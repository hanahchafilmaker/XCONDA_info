## 1. 순서 원칙 — 이 순서를 지켜야 합니다

```
0. 증거·로그 백업  →  1. 인증(근본 차단)  →  2. noindex  →  3. 색인 제거 요청  →  4. 301  →  5. 검증  →  6. 재발 방지
```

- **0번을 건너뛰지 마세요.** 차단 후에는 신규 접속이 사라져 "사고 기간에 누가 들어왔는지"를 다시 만들 수 없습니다.
- **1번(인증)이 진짜 차단**입니다. `noindex` 는 검색 결과에서 빼는 보조 수단이고, URL을 아는 사람에게는 여전히 열립니다.
- **`robots.txt Disallow` 를 먼저 걸지 마세요.** 크롤러가 페이지의 `noindex` 를 읽지 못하게 되어 **색인이 오히려 오래 남습니다.** (§4 참조)

### ⬜ 2단계 — `noindex` 부착 (담당: 개발 · 1일)

**인증을 걸었더라도** 크롤러가 보는 응답에 `noindex` 를 남겨 색인이 재발하지 않게 합니다.

- [ ] **HTTP 헤더 방식(권장)** — 모든 HTML 응답에:
  ```
  X-Robots-Tag: noindex, nofollow, noarchive
  ```
- [ ] **메타 태그 병행**(헤더를 못 넣는 정적 페이지용):
  ```html
  <meta name="robots" content="noindex, nofollow, noarchive">
  ```
- [ ] **canonical 자기 참조 제거/수정** — 현재 `test.` 페이지의 canonical 이 자기 자신을 가리키면 "정식 페이지"로 취급됩니다. `www` 대응 URL을 가리키게 하거나 canonical 을 제거하세요.
- [ ] **sitemap 에서 `test.` URL 제거** — `test.` 도메인 sitemap 을 생성·제출하고 있다면 중단
- [ ] 헤더 확인:
  ```bash
  curl -sI https://test.xconda.ai/pricing | grep -i "x-robots-tag"
  # → X-Robots-Tag: noindex, nofollow, noarchive
  ```

## 3. 하지 말아야 할 것

| ❌ 하면 안 되는 것 | 이유 |
|---|---|
| `robots.txt` 에 `Disallow: /` 만 걸고 끝내기 | 크롤러가 페이지의 `noindex` 를 못 읽어 **기존 색인이 오래 유지**됨 |
| 색인된 URL을 즉시 삭제(404/서버 내리기) | 색인은 남고 유입은 죽은 링크가 됨 → 301로 받아야 함 |
| 로그 백업 없이 차단부터 실행 | 사고 유입 경로를 영구히 잃음 |
| 비밀번호를 저장소·메신저에 평문 기록 | 이 저장소는 **공개 저장소**입니다 |
| 캡처 원본·로그 원본을 이 저장소에 커밋 | 공개 저장소 게시 = 재노출. **해시·집계값만** 기록 |
| "증거를 더 모으자"며 차단 미루기 | 증거는 확보 완료(#1~#6). 지연 사유 없음 |
