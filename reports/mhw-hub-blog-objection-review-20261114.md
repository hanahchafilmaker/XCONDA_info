## 1. 결론 요약

미국 측 의견은 **문제 진단의 방향은 타당하나 기술적 근거는 과장되었고, 해법(새 블로그 구축)은 과함.** 실제 페이지 소스를 확인한 결과 허브의 기술 설정(canonical·hreflang·구조화 데이터·본문 HTML)은 정상이었고, 문제는 화면 문구·제품 사이트 링크·번역 품질에 있었음.

최종 권고는 B안임. **노션 → 허브 발행 방식은 그대로 두고, 영어 허브 전체를 리버스 프록시로 xconda.ai/hub/ 아래에서 보여주는 방안.** 기술팀이 리버스 프록시로 영문 페이지만 서브디렉터리에 연결하는 것이 가능하다고 회신했으므로 실행 조건이 갖춰짐.

| 구분 | 최종 판단 |
|---|---|
| 새 블로그 시스템(MHW안) | 도입하지 않음. 노션 자동 발행을 유지함 |
| 영어 콘텐츠 위치 | 영어 허브 전체(공지·블로그·가이드·Q&A)를 xconda.ai/hub/로 옮김. 블로그만 따로 떼지 않음 |
| 한국어 허브 | hub.xconda.ai 그대로 유지. 한국 X·인스타그램 자동 게시도 현행 유지 |
| 회사 공식 사이트 | 2단계 전환. 현재는 cuberry.kr(회사 소개 + 스튜디오) 유지. cubeberry.ai가 최신 정보로 개선되면 cuberry.kr은 스튜디오 중심으로 바꾸고, 회사 홈페이지는 두 법인을 함께 소개하는 cubeberry.ai로 연결 |
| 문의 메일 | 모든 허브 글(영어·일본어·중국어 포함)은 개발·운영사인 한국 법인 cubeberry@cuberry.kr 유지. 미국 법인(info@cubeberry.ai)은 푸터에서 Stripe 결제 판매사로 표기. 대표 메일(ceo@cubeberry.ai)은 두 법인 공통 대표 메일로 유지 |
| 가장 먼저 고칠 것 | 영어 글 하단 "The Korean hub is the primary source" 문구, 허브 → www 링크 부재, 영어 번역 누락, 끝난 프로모션 노출 |

비유하면 공장(노션)은 그대로 두고, 미국 손님용 안내소를 미국 매장(xconda.ai) 안에 하나 더 차리는 것임. 한국 본점의 종합 안내소(hub.xconda.ai)는 그대로이며, 안내소가 쪼개지는 것이 아님.

## 2. 검토 배경

- **대표 결정(11/13):** xconda.ai/blog는 새로 만들지 않고, 영어 콘텐츠는 hub.xconda.ai에 올림. 노션 연동으로 간편하게 글을 올릴 수 있고, SEO·GEO·AEO 손해가 크지 않다고 봤기 때문임.
- **MHW 주장(11/14):** 한국 허브는 유지하되 미국용 영어 콘텐츠는 xconda.ai 안에 두어야, 콘텐츠 투자가 제품 사이트·가입·결제로 이어짐. "허브 구조로도 같은 성과가 가능하다면 기술적 근거를 달라, 다른 대안도 검토하겠다"고 열어 둠.
- **관계상 맥락:** 11/11 MHW 질문서 답변에서 "/hub/ 이전은 MHW 평가를 받고 함께 결정"이라고 약속했음. 이번 이의 제기는 그 평가에 해당하므로, 의견을 반영해 결정을 조정하는 것이 자연스러움.

## 3. 미국 측 주장별 사실 검증

MHW 영문 원문의 주장을 페이지 소스 기준으로 확인함.

| 미국 측 주장 | 확인 결과 | 판정 |
|---|---|---|
| 구글은 hub.xconda.ai와 xconda.ai를 별개 사이트로 취급함 | 구글 공식 입장은 "서브도메인과 하위 폴더를 대체로 같게 본다"임. 다만 "내용이 밀접하면 같은 사이트에 두라"고 권하고, 현장 SEO 전문가 다수는 하위 폴더가 실제로 유리했다고 보고함 | 일부 맞음(표현 과장) |
| 콘텐츠 효과는 허브에만 쌓이고 xconda.ai는 거의 혜택이 없음 | "거의 없음"은 근거 없음. 다만 허브 글에는 www.xconda.ai로 가는 링크가 없음(예: 블로킹 보드 무료 오픈 공지에 써 보러 가는 버튼이 없음) | 일부 맞음(링크 부족은 사실) |
| 허브는 회사를 cuberry.kr로, 다른 사이트는 cubeberry.ai로 알림 | 허브 회사 정보(JSON-LD)는 cuberry.kr의 주식회사 큐브베리를 가리킴. 이는 XCONDA 개발·운영사가 한국 법인이므로 올바른 연결이며, cuberry.kr과 같은 회사 번호(@id)로 일치함. 빠진 것은 미국 법인(공인 리셀러)과의 관계 표기임 | 현상은 맞음, 해석은 다름 |
| 허브는 한국어 중심이고 공지·AI 뉴스가 섞여 뉴스 사이트로 보일 수 있음 | 첫 화면 기준 공지 12·뉴스 13·가이드 3·블로그 15·Q&A 74건. 혼재는 사실이나 Q&A가 절반 이상이고, Perplexity가 허브 Q&A를 인용한 사례가 있어 단정하기 어려움 | 일부 맞음 |
| 구글에 한국어판이 원본이라고 알리고 있음 | 기술 태그는 정상임(영어 글 lang="en", 자기 canonical, ko·en·ja·zh·x-default hreflang 상호 일치). 그러나 모든 영어 글 하단에 "The Korean hub is the primary source" 문구가 보이고, x-default도 한국어임 | 일부 맞음(태그가 아니라 문구가 원인) |
| AI는 "제품 하나, 사이트 하나, 회사 하나"를 이해하는 도구를 추천함 | 표기·회사 정보 일관성이 중요하다는 원칙은 맞음. 다만 AI는 외부 출처(디렉터리·리뷰·유튜브)를 함께 보므로 블로그 위치보다 외부 언급이 더 큰 변수임 | 일부 맞음 |
| 노력 100을 넣어도 효과는 20~30 | MHW 스스로 "실측치가 아닌 비유"라고 밝힘 | 근거 없음 |
| 단순 번역으로는 부족하며 미국 검색 의도에 맞춘 재작성이 필요함 | 영어 글이 한국어 글의 도입 문단을 빠뜨렸고, 소제목이 제목 태그(h2)가 아님. 화면에 날짜가 없고 글쓴이가 한글("나서영 기획")임. 관련 글에 이미 끝난 프로모션(10/7~11/6)이 노출됨 | 맞음(가장 중요한 지적) |

**주의할 점:** MHW의 한국어 메시지는 "실제 설정이 잘못되었다는 의미는 아니다"처럼 신중하나, 영문 원문은 "별개 사이트", "거의 혜택 없음"처럼 단정적임. 회신은 사실 확인 결과에 근거해 차분하게 정리함.

## 4. 현재 구조 점검 결과

### 허브(hub.xconda.ai)

| 항목 | 상태 | 판단 |
|---|---|---|
| 글별 주소·본문 HTML | 글마다 고유 주소, 본문이 HTML에 있어 AI 봇도 읽음 | 양호 |
| 다국어 설정 | 한·영·일·중 별도 페이지, 자기 canonical, hreflang 상호 연결 | 양호 |
| 구조화 데이터 | 회사·사이트·글 정보 있음. 회사 이름이 "CUBEBERRY"(대문자), 미국 법인 관계 미표기 | 보완 |
| 영어 글 하단 문구 | "The Korean hub is the primary source" | 수정 필요 |
| 제품 사이트 연결 | 글 안에 www.xconda.ai 링크 없음 | 수정 필요 |
| 영어 번역 품질 | 도입부 누락, 날짜 미표시, 끝난 프로모션 노출 | 수정 필요 |

### 회사 사이트

- **cuberry.kr(한국 법인):** 2026년 실적, 대표·팀, 본사·지사 주소, 사업자번호까지 담은 회사 정보가 가장 충실하고 허브와 같은 회사 번호(@id)로 묶여 있음. 「XCONDA 시작하기」는 정상 링크임. 다만 영어판은 서버에 따로 없고 자바스크립트가 화면만 바꾸는 방식이라, AI 봇에게는 한국어판과 링크만 보이지 않는 부분이 있음. 링크에 UTM이 없고, 회사 정보의 sameAs(같은 회사의 다른 공식 주소)가 비어 있음.
- **cubeberry.ai(미국 법인):** 실적 칸 "0+"·"0%" 표시, 출처 없는 "90% faster·70% lower cost", 14개 모델 나열(10/21 포지셔닝과 반대), XConda·XCONDA 표기 혼재, 대표·팀 정보 없음, 현재 핵심 도구(Turn·Flex Board·Blocking Board) 미반영. 개선 전에는 공식 회사 정보로 연결하지 않음.
- **대표 결정 필요:** 11/13 결정대로 cuberry.kr을 "XCONDA와 별개인 스튜디오"로 바꾸면 한국 법인 회사 소개를 둘 곳이 비게 됨. 대표 결정(11/14): 2단계로 전환함. 1단계는 현재처럼 cuberry.kr을 회사 소개 + 스튜디오로 유지함. 2단계는 cubeberry.ai가 최신 정보로 개선된 뒤 cuberry.kr은 스튜디오 중심으로 바꾸고, 회사 홈페이지는 cubeberry.ai로 안내하는 진입점을 둠. 전환 후에도 cuberry.kr 푸터의 한국 법인 정보(사업자·통신판매업 번호, 본사 주소)는 유지하고, cubeberry.ai는 두 법인을 함께 소개하되 한국 법인 내용은 본사 확인 후 반영함. 구조화 데이터는 회사 번호(@id)를 유지하고 url만 바꿈.

### 두 법인의 역할과 문의 메일

사이트 푸터에 두 법인의 역할이 이미 분명히 나뉘어 있음.

| 법인 | 역할 | 문의 메일 | 표시 위치 |
|---|---|---|---|
| 주식회사 큐브베리(한국) | XCONDA 개발·운영사 | cubeberry@cuberry.kr | 모든 허브 글(영어 포함), cuberry.kr, 푸터 |
| Cubeberry Co., Ltd(Delaware) | Stripe 결제를 자기 명의로 판매·청구하는 공인 리셀러 | info@cubeberry.ai | cubeberry.ai, 푸터 |
| 두 법인 공통 | 대표(이진서) | ceo@cubeberry.ai | 회사 정보, IR·발표 자료 |

XCONDA 기능·사용법·크레딧 질문은 개발·운영사인 한국 본사만 답할 수 있으므로, 영어 허브 글에도 한국 법인 메일을 붙이는 현재 방식이 맞음. 대표 메일은 두 법인 공통 대표를 가리키고 계정도 대표가 직접 통제하므로 문제가 없음. 일본어·중국어 페이지도 같은 이유로 한국 법인 메일을 유지함(11/14 대표 결정).

## 5. 선택지 비교와 결론

| 항목 | A안 현행 유지+보강 | B안 영어 허브 경로 통합(권고) | C안 신규 블로그(MHW안) |
|---|---|---|---|
| 내용 | 영어는 hub.xconda.ai/en/에 두고 문구·링크·번역만 고침 | A안 + 영어 허브 전체를 리버스 프록시로 xconda.ai/hub/에서 제공 | xconda.ai에 새 블로그(별도 CMS)를 만들어 영어 글을 따로 발행 |
| 개발 공수(추정) | 2~3일 | A안 + 3~7일 | 2~4주 + 상시 유지보수 |
| 노션 자동 발행 | 유지 | 유지 | 영어는 별도 입력(이중 관리) |
| 메인 도메인에 검색 점수 축적 | 낮음(링크로 간접 전달) | 높음 | 높음 |
| 허브의 종합 안내 역할 | 유지 | 언어별로 유지 | 블로그와 허브가 쪼개짐 |
| MHW 요구 충족 | 부분 | 대부분 | 전부 |
| 주요 위험 | 미국 측과 갈등 지속, 나중에 이전 비용 증가 | 프록시 설정 실수 시 일시 오류, 기존 /en 주소 301 필요 | v2.6·Stripe 개발 지연, 한·미 콘텐츠 사실 불일치 |

**B안 실행 원칙**

1. **영어 허브 전체를 옮김.** 블로그만 옮기면 영어 사용자에게 허브가 두 곳으로 쪼개짐. 공지·블로그·가이드·Q&A 영어판을 모두 옮김.
2. **경로 이름은 /blog가 아니라 /hub/.** 내용이 블로그만이 아니고, v2.6 헤더의 "Hub" 메뉴(Guides·Q&A·News)와 이름이 맞으며, 11/11 MHW 답변의 "/hub/ 이전" 표현과도 일치함. 예: xconda.ai/hub/post/..., xconda.ai/hub/qna/...
3. **한국어는 hub.xconda.ai에 그대로 둠.** 서로 다른 도메인이어도 hreflang을 주소 전체로 서로 가리키게 하면 검색엔진은 같은 글의 언어별 버전으로 인식함(구글 공식 지원).
4. **일본어·중국어는 당분간 hub.xconda.ai에 둠.** 영어 성과를 본 뒤 함께 정함.
5. **지금 옮기는 것이 가장 쌈.** 영어 원본 글이 쌓이기 전이라 리다이렉트할 주소가 적고, 미국에서 쌓인 검색 점수도 거의 없음.

앞의 2순위는 **글 페이지에만** 제품 링크를 넣었음. 그런데 검색 결과에서 글이 아니라 **목록 페이지**(`/post/`, `/en/qna/` …)나 **홈**으로 들어오는 방문자에게는 여전히 제품 사이트로 갈 길이 없었음 — MHW가 지적한 "허브에서 제품으로 가는 연결 부족"이 절반만 고쳐진 상태였음.

- 홈(한국어)과 모든 섹션 목록(한·영·일·중)에 「무료로 시작하기 · 요금 보기」 링크를 넣음. 글 페이지와 **같은 UTM 규칙(§6-1)** 을 쓰고, `data-cta-scope="listing"` 으로 글 페이지 링크와 구분함.
- 영어가 `www.xconda.ai/hub/` 로 옮겨진 뒤에는 그 목록이 제품 사이트 안이 되므로 UTM을 붙이지 않음(글 페이지와 같은 처리).
- 고친 곳: `src/content/cta.js`(`listingLinks`), `scripts/build-seo.mjs`(`listingLinksHtml` · 홈 · 섹션 목록 · 언어별 홈/목록). 테스트: `scripts/seo.test.mjs`.

**확인하면서 새로 발견한 것**

- 빌드 경고 "본문에 노션 파일 주소가 남아 있습니다"가 **정상 동작을 문제로 표시하고 있었음.** 본문 이미지는 노션 공개 프록시(`www.notion.so/image/…`)로 바꿔 내보내는 것이 정상인데(`signNotionImage`), 경고가 `<img src>`까지 잡아 **발행 글 17~18건이 매 빌드마다 경고**로 올라왔음. 진짜 문제(다운로드·PDF 링크가 노션 주소인 경우, 프록시로 감싸지 못한 원본 주소가 본문 텍스트에 남은 경우)만 경고하도록 고침. 지금은 0건.
- 영어 Q&A 73건 중 65건이 **답변 없이 "Source"(출처)만 화면에 보이고 있었음.** 영어 Q&A는 요약(Summary)이 곧 답변인데, 본문 블록(출처)이 있으면 요약을 화면에서 빼는 규칙 때문이었음. 3순위 ①(도입 문단 복원)과 같은 원인이라 함께 고쳐짐. 의견서의 "도입 문단 누락"보다 영향이 큰 문제였음.
- 끝난 프로모션 두 글(`seedance-2-5-promotion-30-off`, `seedance-30-off-package-quantities`)은 한국어만 "종료"로 고쳐져 있었고 영·일·중 제목·요약은 "진행 중"이었음 → 세 언어의 제목·요약을 종료 표기로 고침. 본문은 당시 공지 그대로이며 상단에 종료 안내가 붙음.

**UTM (11/14 최종)**

- 허브 글의 제품 사이트 링크에 UTM을 붙임: `utm_source=hub&utm_medium=referral&utm_campaign=hub_cta_202611&utm_content=cb_top|cb_bottom`
- 확정된 UTM 규칙 v1.0의 허용값은 외부 채널용이라 맞는 값이 없어, 허브 전용 조합을 규칙 문서 §6-1로 추가하고 검사기가 `www.xconda.ai` 도착 링크에서만 통과시키게 함. 같은 날 한 차례 제거했다가(PR #125) 대표 요청으로 다시 적용함.
- **남은 일:** `hub_cta_202611`을 운영 시트 「캠페인 Campaigns」 탭에 등록하고, Word·Notion 규칙 본문에 §6-1을 반영함.
- **알고 써야 할 점:** 허브와 www가 같은 GA4 속성이면 이 UTM이 방문자의 원래 유입(예: 인스타 → 허브)을 덮어써, 제품 사이트 쪽 기록은 `hub / referral`이 됨.

**영어 허브 하위 폴더 이전 준비 (11/14 · 5순위의 허브 쪽 작업)**

- 영어 주소를 `www.xconda.ai/hub/…`로 바꾸는 스위치를 만듦: `src/content/seo.js`의 `LOCALE_BASE_URLS.en`. **지금은 꺼져 있어 사이트는 그대로임.**
- 켜면 영어 페이지의 canonical·og:url·구조화 데이터, 모든 언어의 hreflang `en`과 언어 전환 링크, 사이트맵(영어분은 `en/sitemap.xml`로 분리), `llms.txt`가 새 주소로 바뀜. 예전 주소 `hub.xconda.ai/en/…` 방문자는 같은 글의 새 주소로 이동함(UTM 유지).
- 켠 상태에서 영어 페이지의 제품 링크에는 UTM을 붙이지 않음(같은 사이트 안 이동이 되므로). 한·일·중은 그대로 붙음.
- 제품 사이트 쪽 프록시가 먼저 필요함. 개발자 전달 사항: `reports/en-hub-subdirectory-handoff-20261114.md`. 프록시 점검: `npm run proxy:check`.
- GitHub Pages는 서버 301을 낼 수 없어 예전 주소는 canonical과 스크립트 이동으로 처리함(「기술팀에 확인할 5가지」 4번).

**끝난 행사 글 표시 방법(운영)**: 노션 제목이나 SEO 제목에 `(종료)` 또는 `(10/7~11/6, 종료)`처럼 괄호 안에 "종료"를 넣으면 관련 글 추천에서 빠지고, 번역 페이지에 종료 안내가 붙음.
