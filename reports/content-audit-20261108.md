## 5. 이번 사고와 겹치는 위험 3가지

### 5.1 Notion 동기화가 11/07 21:25Z부터 51회 연속 실패했습니다

`Notion 스냅샷 생성` 단계에서 매번 실패했고, **사이트는 11/07 22:08Z 스냅샷에 멈춰 있습니다**(점검 시점 기준 4시간 경과). 실패는 아무 데도 알림이 가지 않았습니다.

- 영향: 노션에 새 글·수정을 넣어도 사이트에 반영되지 않음 → **발행 체크리스트를 운영해도 결과가 사이트에 안 나타남**
- 원인 후보(추측 금지): `NOTION_TOKEN` 만료/권한 회수, DB ID 변경, 노션 쪽 오류. 확인 순서는 새로 추가한 **실행 요약**에 자동으로 남습니다
- 제가 이번에 고친 것: 실패해도 **요약과 경고를 남기고**, 실패 시 **게시·커밋을 건너뛰도록** 워크플로를 바꿨습니다(옛 스냅샷을 새 것처럼 올리지 않음)

### 5.2 "테스트 서버 차단"은 SEO 백로그가 아니라 **보안 항목**입니다

계획서 판단에 동의합니다. 다만 이 저장소에는 테스트 서버 주소·설정이 없어 제가 확인할 수 없었습니다(`dev.html` 은 이미 `noindex, nofollow`, `dist-test/` 는 `.gitignore`). 확인 주체는 개발입니다.

**순서를 반드시 지켜야 합니다.** 차단·noindex 를 먼저 하면 증거가 사라집니다.

| 순서 | 할 일 | 담당 | 시점 |
|---|---|---|---|
| 1 | Search Console > 색인 > 페이지에서 테스트 서버 주소 캡처(색인된 URL·최초 색인일) | 대표(권한 이전 전) | **차단 전** |
| 2 | `site:테스트서버주소` 검색 결과 전체 화면 캡처(날짜 보이게) | 대표 | **차단 전** |
| 3 | 캡처 파일을 사고 증거 폴더에 보관 + 수집 일시·수집자 기록 | 차하나 PD | 즉시 |
| 4 | 테스트 서버 접근 차단(IP 제한/VPN) 또는 인증 추가, `noindex` 병행 | 개발 | 보안 수정 48시간 내 |
| 5 | 차단 후에도 **증거 캡처는 삭제하지 않음** | 전원 | 상시 |

> 색인 현황은 "언제부터 노출됐는지"가 핵심입니다. Stripe 사고 발생(11/06) 이전에 색인됐다면 **공격자가 검색으로 찾았을 가능성**을 배제할 수 없고, 이후라면 인과관계가 약해집니다. 어느 쪽이든 **캡처 시각이 곧 증거**입니다.

### 5.3 공개 저장소에 사고 문서를 두는 문제 — 조치 완료, 결정은 남음

`reports/` 는 GitHub Pages 로 공개됩니다. PR #112 에서 `robots.txt` 에 `Disallow: /reports/` 를 넣고 생성기·테스트까지 고정했습니다(색인 차단). 다만 **접근 제어는 아니므로** 비공개 이관 여부는 대표 결정 사항으로 남아 있습니다.
