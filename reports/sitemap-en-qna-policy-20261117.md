## 2. 왜 바꿨나 — 2026-10-26 정책의 전제가 사실이 아니게 됨

기존 정책의 근거는 두 가지였습니다. 둘 다 다시 확인했습니다.

### ① "얇은 페이지" — **사실이 아님**

영어 Q&A 73개 본문을 실측(스크립트 태그·태그 제거 후 단어 수):

| 측정 | 값 |
| --- | --- |
| 평균 | **151단어** |
| 최소 | 106단어 (`how-to-access-hub`) |
| 100단어 미만 | **0건** |
| 150단어 이상 | 33건 |

한국어 원문 같은 글(`qna/commercial-use`)과 비교하면 **영어가 더 깁니다**
(한국어 167단어 → 영어 219단어). 영어 페이지는 도입 문단 + 본문 + 출처 + 문의처가
모두 실려 있고, `hreflang` 도 9개(한국어 5개)로 더 완비돼 있습니다.

원인: 2026-11-14 MHW 검토 3순위에서 **"영어 Q&A 73건 중 65건이 답변 없이 출처만 보이던 문제"**
(요약=답변인데 본문 블록이 있으면 요약을 빼던 규칙)를 고쳤습니다. 그 수정으로
영어 Q&A가 실제 답변을 갖춘 페이지가 됐습니다.

### ② "영어는 색인 대상이 아니다" — **전제가 뒤집힘**

2026-11-17 에 영어 허브 전체가 `www.xconda.ai/hub/` 로 옮겨졌습니다(PR #141).
영어는 이제 **제품 사이트의 주 언어**이고, 영어 Q&A는 크롤 예산을 아낄 대상이 아니라
**색인이 필요한 자산**입니다. 첫날 Search Console 에 `/hub/sitemap.xml` 을 제출해
22개가 정상 수집된 것으로 확인했습니다.

## 3. 위험과 완화 (품질 보강)

기존 정책의 경고: 2026-11-10 Search Console **"발견됨 - 현재 색인이 생성되지 않음 324건"**.
이 수치는 **변경 전** 것이고, Q&A 뿐 아니라 다른 요인(페이지당 540KB 인라인 번들 등)도 섞여 있습니다.
그래서 영어만 넣고 관찰합니다.

| 위험 | 확인 결과 / 완화 |
| --- | --- |
| 얇은 페이지 대량 색인 | ✅ 평균 151단어 · 100단어 미만 0건 |
| 발견 경로 없음(사이트맵만 의존) | ✅ 영어 Q&A 73개 **전부** 한국어 원문에서 `hreflang="en"` 링크로 도달 가능 (73/73) |
| 목록 페이지가 얇음 | ✅ `/en/qna/` 606단어(73개 링크 목록) — 제외하지 않고 포함 |
| 구조화 데이터 없음 | ✅ 73개 모두 `FAQPage` |
| 사이트맵 URL 오류 | ✅ 74개 전부 실제 배포 파일과 1:1 대응 (누락 0) |
| ja·zh 까지 함께 색인 | ✅ 계정 배열로 분리 — ja/zh 는 계속 제외 (허브 사이트맵에 0건 확인) |

**관찰 계획**: 배포 후 Search Console 에서 2~4주
- `xconda.ai` 속성 → 사이트맵 → `/hub/sitemap.xml` 재수집 (96개 확인)
- 색인 생성 수 / "발견됨 - 색인 생성 안 됨" 추이
- 영어 Q&A 73개 중 색인된 비율

색인율이 낮거나 "발견됨" 이 다시 급증하면 `en: ["qna"]` 로 되돌립니다.
