# XCONDA UI/UX 개선 · 검증 기록

검증일: 2026-11-15. 기존 React 19 · Vite · Tailwind CSS 4 및 정적 배포 구조를 유지했습니다.

## 적용 범위

### 1. shadcn/ui
- `src/components/ui/`에 Button, Dialog, Command, Sonner 래퍼를 소스 형태로 도입했습니다.
- shadcn/ui MIT 라이선스는 같은 폴더에 보존했습니다. XCONDA의 흰색·아이보리·노란색 테마에 맞춰 수정했으며 기본 테마를 통째로 덮어쓰지 않았습니다.
- 검색창에 Radix Dialog의 포커스 가두기, Esc/배경 클릭 닫기, 스크롤 잠금을 적용했습니다. 검색 중 배경 앱은 `inert` 상태가 됩니다.
- 검색 닫기 및 검색 → 글 상세 → 닫기에서 원래 실행 버튼으로 포커스가 복귀합니다.
- 공유·코드 복사·검색 필터에 공통 Button을 적용했습니다. 기존 글 상세/HTML 가이드 모달 전체를 교체하지는 않았습니다.

### 2. cmdk 검색
- ↑↓ 탐색, Enter 열기, Esc 닫기, Ctrl/Cmd+K 및 `/` 진입.
- 한글/일본어 IME 확정 Enter가 글을 열지 않도록 보호.
- 입력 필드, contenteditable 및 기존 모달에서는 전역 검색 단축키를 실행하지 않음.
- 제목·요약·카테고리·날짜·태그를 검색하고 제목 완전 일치/접두 일치를 우선 정렬.
- NFKC 정규화, 대소문자 구분 없는 검색, 공백으로 구분한 여러 검색어의 AND 매칭.
- 종류 필터의 선택 상태, 검색어 지우기, 빈 결과 초기화, 24개 단위 더 보기와 전체 일치 건수 표시.
- 메인 키워드는 검색창에 전달하되 헤더에서 다시 열 때는 이전 검색어/필터를 초기화.
- cmdk는 키보드 선택 UI로 사용하며 실제 검색과 정렬은 앱에서 수행합니다.

### 3. Sonner
- 링크 공유와 코드 블록 복사 모두 Clipboard API의 Promise가 성공한 뒤에만 성공 알림을 표시합니다.
- API 부재 및 권한 거절 시 오류 알림을 표시합니다. 실패를 성공으로 표시하던 기존 동작을 제거했습니다.
- 복사 처리 중 버튼을 비활성화하며, 한국어/영어 알림 문구는 기존 사전에 추가했습니다.
- 일본어/중국어 UI는 기존 번역 체계를 그대로 따릅니다. 새 번역 엔진을 추가하지 않았습니다.

### 4. 접근성 보정
- 아이보리 패널/선택 행에서 회색 보조 텍스트·노란색 링크·배지의 대비를 높였습니다.
- 닫힌 모바일 메뉴는 `inert` 및 `aria-hidden`으로 키보드/보조기술 탐색에서 제외합니다. 메뉴 Esc 닫기와 실행 버튼 포커스 복귀를 추가했습니다.
- 코드 블록을 밝은 배경으로 정리하고, 가로 스크롤 영역에 접근 가능한 이름과 키보드 포커스를 부여했습니다.
- 기존 reduced-motion 규칙을 유지합니다.

## 검증

- `npx tsc --noEmit`: 통과. 기존 `syncHealth.js`의 누락된 타입 선언도 보완했습니다.
- `npm run test:unit`: 281개 단위 테스트 및 콘텐츠 분류 스모크 통과.
- `npm run test:smoke`: 검색, 글 상세, HTML 가이드, 동기화, 언어 전환, SEO/공유 회귀 통과.
- `npm run test:ui`: Chromium 브라우저 시나리오 7개 통과.
  - 키보드 선택, IME, 글 열기/닫기, 포커스 복귀
  - 필터의 Enter 조작, 빈 결과, 초기화, 더 보기, 메인 키워드와 재진입
  - 정방향/역방향 Tab 가두기, 배경 클릭, 단축키, 편집 필드 보호
  - 링크/코드 복사 성공·권한 거절·API 부재
  - 데스크톱 홈/검색/빈 결과, 모바일 390×844 검색, 영문 검색과 글 상세
- axe-core: 위 자동 검사 상태에서 WCAG 2 A/AA 및 2.1 A/AA 태그의 **확정 위반 0건**.
- `npm run build`: 통과. `assets/app.js`와 `assets/app.css`는 빌드로 생성했습니다.
- `npm audit`: 발견된 취약점 0건. 기존 개발 의존성의 전이 패키지 `undici`도 수정 버전으로 갱신했습니다.

## 재실행

```bash
npm ci
npx playwright install --with-deps chromium
npm run test:ui
# 접근성 검사만
npm run test:a11y
```

`playwright.config.ts`는 실제 사용자 UI를 검사하도록 일반 Chrome User-Agent를 사용합니다. 기본 HeadlessChrome UA는 이 프로젝트의 의도된 크롤러 정책에 의해 한국어로 고정되기 때문입니다.

샌드박스에서는 설치된 Chromium 실행 파일을 `CHROMIUM_EXECUTABLE_PATH`로 지정해 검증했습니다. 한국어 글리프의 시각 확인에는 별도로 준비한 Noto Sans KR을 사용했으며 브라우저/폰트 바이너리는 저장소에 넣지 않았습니다. 일반 환경과 CI에서는 Playwright의 Chromium 설치 명령을 사용합니다.

PR 및 수동 실행용 `.github/workflows/ui-checks.yml`을 추가했습니다. 실패 trace는 7일간 CI 아티팩트로 보존합니다. 브라우저 테스트에서 외부 서비스 요청은 차단하고 로컬 콘텐츠를 사용합니다. axe-core와 Playwright는 개발 의존성이며 운영 번들에 포함하지 않습니다.

## 제한 및 후속 확인

- 자동 검사 통과는 전체 사이트의 접근성 인증이 아닙니다. axe의 `incomplete` 결과(그라데이션/이미지 위 대비, 일부 ARIA/빈 목록 판정 등)는 테스트 첨부 결과에 남기며 위반 0건과 구분합니다.
- VoiceOver/NVDA 실제 낭독, 터치 스크린리더, 모바일 가상 키보드, 외부 영상 iframe 및 Google 실시간 번역 후 DOM은 별도 수동 검수가 필요합니다.
- 콘텐츠가 바뀌면 대비/구조 검사는 다시 실행해야 합니다.
- 빌드에 남은 기존 번역 원고의 원문 누락·블록 수 불일치 경고는 이번 UI 작업 범위 밖이며 수정하지 않았습니다.
- shadcn/Radix/cmdk/Sonner 도입으로 운영 JS gzip은 기존 대비 약 30KB 증가했습니다. 현재 단일 번들 배포 구조를 유지했으며 추가 UI 도입 시 번들 크기도 함께 확인해야 합니다.
- 운영 배포·Git push·PR 생성은 수행하지 않았습니다.
