# 허브 언어 정책 — 영어 먼저, 한국어 두 번째

- 작성일: 2026-11-15
- 근거: 큐브베리원 대표 슬랙 지시(2026-11-15 19:24)

  > 기본을 엑스콘다 처럼 영어로 두고 두번째에 한국어로 두는게 좋겠어요. 허브에 글은 지금처럼 한국어로 쓰지만 내년에 정식버전 부터는 영어로 글을 먼저 올리는게 어떨까 해요.

- 적용 범위: 허브(`hub.xconda.ai`)의 **언어 목록 순서**와, 내년 영어 원문 발행을 위한 **대표 언어 스위치 준비**

## 1. 결정을 이렇게 나눴습니다

| 항목 | 지금(2026-11-15) | 내년 정식버전(영어 원문 발행 시작) |
|---|---|---|
| 언어 목록 순서 | **English → 한국어 → 日本語 → 中文** (반영 완료) | 그대로 |
| 글 작성 언어 | 지금처럼 **한국어 원문 먼저** → `/en/`·`/ja/`·`/zh/` 번역 | **영어 원문 먼저** → 한국어·일본어·중국어 번역 |
| 대표 언어(`x-default`) | **한국어**(`PRIMARY_LANG = "ko"`) | `PRIMARY_LANG = "en"` 한 줄 전환 |
| 한국어 주소 | `/` (접두사 없음, 원문) | `/` 유지 — 주소는 바꾸지 않습니다 |

핵심은 **"화면 순서"와 "대표 언어"를 분리**한 것입니다. 순서는 오늘 바꾸고, 대표 언어는 콘텐츠 원문이 영어로 넘어가는 시점에 바꿉니다. 순서만 바꿔서는 canonical·hreflang·사이트맵·색인에 아무 변화가 없습니다.

## 2. 오늘 반영한 것

| 파일 | 변경 |
|---|---|
| `src/components/Nav.tsx` (`LANG_ITEMS`) | 앱 내비 토글 순서 EN → KO → JA → ZH |
| `src/content/seo.js` (`SITE_LANGS`) | 정적 페이지 언어 목록 순서 EN → KO → JA → ZH (배열 순서 = 표시 순서) |
| `src/content/seo.js` (`PRIMARY_LANG` · `setPrimaryLang`) | 대표 언어 스위치 추가 — 지금은 `"ko"`. 번역이 없는 글은 스위치를 켜도 계속 한국어를 `x-default` 로 씁니다(없는 주소를 대표로 선언하지 않음) |
| `src/content/seo.js` (`hreflangAlternates`) | `x-default` 를 `PRIMARY_LANG` 기준으로 계산 |
| `src/components/seo.d.ts` | `PRIMARY_LANG` · `setPrimaryLang` 타입 |
| `scripts/seo.test.mjs` | ① 언어 목록이 EN·KO·JA·ZH 순서인지 ② 정적 언어 전환 목록이 영어→한국어인지 ③ 스위치를 켜면 **영어 번역이 있는 글만** 영어가 `x-default` 가 되는지 |
| `scripts/smoke.mjs` | 토글 코드 순서 기대값 `["EN","KO","JA","ZH"]` |
| `index.html` · `en/` · `ja/` · `zh/` · `assets/app.js` 등 | 빌드 산출물 재생성(295개 파일, 언어 목록 순서만 변경) |

검증: `npm run test:unit` · `npm run test:smoke` 통과.

## 3. 바뀌지 않은 것 (의도)

- **콘텐츠 원문은 한국어**입니다. 노션 작성·`content/i18n/<언어>.json` 번역 구조 그대로입니다.
- **대표 주소(canonical)·hreflang `ko`·`x-default`** 는 계속 한국어 원문을 가리킵니다.
- **크롤러·AI 봇에게는 계속 한국어 원문**을 돌려줍니다(`isCrawlerUA`). 기본 언어를 성급히 영어로 바꾸면, 아직 영어 원문이 없는 글에서 기계번역 본문이 검색 대표가 됩니다.
- 사이트맵·`llms.txt`·OG 카드 산출물 구성은 그대로입니다(순서만 달라짐).

## 4. 내년에 영어 원문을 먼저 올릴 때 (체크리스트)

1. 영어 원문 글을 노션에 먼저 쓰고, 한국어 번역을 `content/i18n/ko.json` 성격으로 붙입니다(현재 구조를 뒤집을 때는 `build-seo.mjs` 의 원문 기준 언어를 함께 손봐야 합니다 — 그때 별도 작업).
2. 영어 번역이 **주요 섹션(공지·블로그·가이드)까지** 채워졌는지 `npm run i18n:progress` 로 확인합니다.
3. `src/content/seo.js` 의 `PRIMARY_LANG` 을 `"en"` 으로 바꿉니다 — 이 한 줄이면 `x-default` 가 영어로 넘어갑니다.
4. `npm run build` → `npm run test:unit` → `npm run test:smoke` → 배포.
5. Search Console 에서 `x-default`·`hreflang` 인식과 영어 페이지 색인을 2~4주 관찰합니다.
6. 문제가 생기면 `PRIMARY_LANG` 을 `"ko"` 로 되돌리고 다시 배포합니다(데이터 손실 없음).

> ⚠️ 영어 허브를 `www.xconda.ai/hub/` 로 옮기는 프록시 작업(`LOCALE_BASE_URLS`)과 **순서를 섞지 마세요.** 프록시는 "영어 페이지가 어느 주소로 보이는가", `PRIMARY_LANG` 은 "어느 언어가 대표인가"입니다. 두 스위치 모두 한 줄이고 서로 독립입니다.

## 5. 슬랙 회신 문안 (그대로 복사)

```text
큐브베리원님, 말씀 주신 대로 *영어를 기본(첫 번째), 한국어를 두 번째*로 바꿔 배포 준비했습니다.

*오늘 바꾼 것*
• 허브 언어 선택 목록 순서: English → 한국어 → 日本語 → 中文
  (데스크톱·모바일 토글, 정적 페이지의 언어 링크 모두 같은 순서)
• 주소·검색 정보(canonical·hreflang)는 그대로입니다 — 순서만 바꿔서 검색에 미치는 영향은 없습니다.

*지금은 그대로 둔 것*
• 글은 지금처럼 *한국어 원문 먼저* 쓰고 번역을 붙입니다.
• 검색엔진에 알리는 *대표 언어는 아직 한국어*입니다. 영어 원문이 아직 없는데 영어를 대표로 선언하면, 번역기로 돌린 본문이 검색 대표가 될 수 있어서입니다.

*내년 정식버전 준비*
• 영어 원문을 먼저 올리기 시작할 때 *한 줄*(`PRIMARY_LANG`)만 바꾸면 대표 언어가 영어로 넘어가도록 스위치를 만들어 두었습니다.
• 영어 번역이 없는 글은 그대로 한국어를 대표 주소로 쓰기 때문에, 미리 켜 두어도 색인이 흔들리지 않습니다.
```
