Writing Workflow

글 작성 절차

신규 글 기준의 표준 절차입니다. 기존 글 수정도 ②~⑥ 순서로 동일하게 진행합니다.

  1. Notion DB에서 새 행을 추가합니다

    데이터베이스 오른쪽 위 New 또는 표의 새로 만들기를 누릅니다. 생성 즉시 Published가 꺼져 있는지 먼저 확인하고, 행을 페이지로 열어 작성합니다.

  2. Title · Type · Date를 먼저 입력합니다

    세 항목은 모든 콘텐츠의 필수값입니다. Type은 공지 / 업데이트 / 가이드 / FAQ 중 정확히 하나를 선택하고, Date에는 실제 게시 기준일을 입력합니다.

    • Title: 목록과 상세 모달에 표시되는 제목. 핵심 내용을 앞쪽에 작성
    • Type: 글이 노출될 사이트 영역을 결정
    • Date: 공지·업데이트 정렬과 날짜 표시에 사용

  3. Summary · Category와 유형별 필드를 채웁니다

    Summary는 목록 카드에서 내용을 이해할 수 있는 1~2문장으로 작성합니다. 업데이트는 Version / Changes, 가이드는 Tool / Order, 긴급 공지는 Pinned / Important를 추가로 확인합니다.

  4. 페이지 본문에 상세 내용을 작성합니다

    표의 속성 영역 아래 페이지 본문에 내용을 씁니다. 헤딩으로 구조를 나누고, 단계는 번호 목록, 주의사항은 콜아웃, 보충 설명은 토글을 사용하면 상세 모달에서 읽기 쉽습니다.

  5. 미리 검수한 뒤 Published를 체크합니다

    오탈자, 날짜, 링크, 이미지, 유형별 필드를 확인한 후 Published를 체크합니다. 체크된 글만 다음 동기화 대상에 포함됩니다.

  6. 사이트 반영을 확인합니다

    자동 동기화는 10분 주기로 실행됩니다. 급하면 GitHub Actions의 Notion 동기화를 수동 실행하고, 완료 후 사이트에서 목록 위치와 상세 모달을 함께 확인합니다.

Page Body

상세 본문 작성법

페이지 속성 아래의 본문은 사이트 상세 모달에 표시됩니다. 목록에서 빠르게 이해할 정보는 Summary에, 실제 절차와 설명은 본문에 작성합니다.

권장 본문 구조

  • 첫 문단: 이 글의 목적과 대상 사용자를 2~3문장으로 설명
  • Heading 2: 큰 주제나 작업 단계를 구분
  • 번호 목록: 순서대로 해야 하는 작업
  • 불릿 목록: 옵션, 조건, 참고 사항
  • 콜아웃: 경고, 제한, 꼭 알아야 할 내용
  • 토글: 긴 보충 설명이나 선택적 세부 내용
  • 마지막: 다음 행동, 관련 링크, 문의 경로

사이트에서 지원하는 블록

Heading 1–3ParagraphBulleted listNumbered listChecklistQuoteCalloutCodeImageYouTubeBookmarkToggleDivider

작성 팁: 한 문단을 지나치게 길게 쓰지 말고, 모바일 화면을 고려해 3~5문장마다 헤딩·목록·이미지로 호흡을 나눕니다.

🖼️
이미지는 외부 URL 방식을 권장합니다.
Notion에 직접 업로드한 파일 URL은 약 1시간 후 만료될 수 있습니다. 장기간 노출할 커버와 본문 이미지는 안정적인 외부 이미지 호스팅의 공개 https:// URL로 삽입하고, 게시 후 시크릿 창 또는 다른 기기에서도 열리는지 확인하세요.
Publish & Verify

게시와 반영 확인

Published를 체크하면 다음 동기화가 글을 정적 스냅샷에 포함합니다. 체크 즉시가 아니라 동기화 완료 후 사이트에 노출됩니다.

일반 게시 · 자동 동기화

  1. 필수 필드와 본문을 최종 검수합니다.
  2. Published를 체크합니다.
  3. 최대 10분 동안 자동 동기화를 기다립니다.
  4. 사이트 탭으로 돌아오거나 상단 동기화 배지의 새로고침을 누릅니다.
  5. 목록 카드와 상세 모달을 각각 확인합니다.
✓
사이트는 약 3분마다, 탭으로 돌아올 때, 상단 새로고침 버튼을 누를 때 최신 스냅샷을 다시 읽습니다.

긴급 게시 · 수동 동기화

  1. GitHub Actions → Notion 동기화 ↗를 엽니다.
  2. Run workflow를 누릅니다.
  3. 사이트가 운영되는 브랜치를 선택하고 다시 Run workflow를 누릅니다.
  4. 실행 결과가 초록색 체크로 완료될 때까지 기다립니다.
  5. 사이트에서 새로고침 후 노출을 확인합니다.
!
빨간 X가 표시되면 실행 항목을 열어 Notion 스냅샷 생성 단계의 오류 로그를 확인하세요. 실패한 상태에서는 Published를 반복 체크해도 반영되지 않습니다.

게시 후 반드시 확인할 4곳

  • 목록: 올바른 섹션과 정렬 위치에 있는가
  • 카드: 제목·요약·날짜가 잘리지 않고 이해되는가
  • 상세: 본문·이미지·링크·토글이 정상인가
  • 모바일: 긴 제목과 이미지가 화면을 넘지 않는가
Emergency Notice

긴급 공지 운영

장애, 긴급 점검, 결제 영향처럼 사용자가 즉시 알아야 할 내용에만 사용합니다. 동기화 완료 후 히어로 배너와 공지 목록 최상단에 우선 노출됩니다.

🚨 긴급 공지 필수 설정

Pinned는 위치를, Important는 시각적 강조를 담당합니다.

운영자 즉시 확인
Type공지
Pinned✓ ON

게시 순서

  1. 제목에 영향 범위와 상태를 명시
  2. Summary에 사용자가 지금 해야 할 행동 작성
  3. 본문에 시작 시각·영향·대응·다음 안내 시각 작성
  4. Pinned + Important 체크 후 Published 체크
  5. Actions 수동 실행 → 사이트 확인

종료·해제 순서

  1. 복구 시 제목 또는 본문에 해결됨 표기
  2. 더 이상 최상단 고정이 필요 없으면 Pinned 해제
  3. 강조가 필요 없으면 Important 해제
  4. 공지 자체를 내리려면 Published 해제
  5. 변경 후 다시 동기화하고 사이트 확인
⚠️
Pinned 공지는 꼭 필요한 항목만 유지하세요. 여러 공지에 Pinned가 체크되어 있으면 날짜가 최신인 고정 공지가 먼저 표시됩니다. 긴급 상황 종료 후 고정을 해제해야 다음 중요 공지가 히어로에 정상 노출됩니다.

Fixed · 수정

오류·버그 해결

기존 동작의 오류, 표시 문제, 모바일·브라우저 버그 수정.

  • Notion 페이지 링크로 내부 검수 진행
  • 필수값과 본문을 완료한 뒤 게시 체크리스트 확인
  • 최종 승인자가 Published 체크

✏️ 게시 글 수정·회수

  • 간단한 오탈자는 기존 행에서 바로 수정
  • 큰 수정은 Published를 잠시 해제한 뒤 작업 권장
  • 사이트에서 내리려면 Published 해제
  • 수정·회수 후에도 다음 동기화가 완료되어야 반영

🔗 사이트 글 공유

  • 사이트에서 해당 글의 상세 모달 열기
  • 오른쪽 위 공유 버튼 클릭
  • #post=페이지ID가 포함된 링크 복사
  • 로그아웃·시크릿 창에서 링크가 바로 열리는지 확인

미공개 글은 사이트 데이터에 없으므로 공유 링크로도 열리지 않습니다.

🖼️ 이미지 운영

  • 장기 노출 이미지는 외부 공개 URL 사용
  • 접근 권한이 필요한 사내 URL 사용 금지
  • 가로 폭이 과도하게 큰 원본은 웹용으로 최적화
  • 게시 후 데스크톱·모바일·시크릿 창에서 확인

Notion 직접 업로드 파일은 서명 URL 만료로 나중에 깨질 수 있습니다.

Troubleshooting

문제가 생겼을 때

위에서 아래 순서로 확인하면 대부분의 콘텐츠 운영 문제를 해결할 수 있습니다.

증상먼저 확인할 것해결 방법
10분이 지나도 글이 안 보임Published, Title, Type, Date / Actions 실행 상태필수값을 다시 확인하고 Notion 동기화를 수동 실행. 빨간 X면 오류 로그 확인
다른 섹션에 나타남Type 값Type을 공지·업데이트·가이드·FAQ 중 올바른 값으로 변경 후 재동기화
긴급 공지가 최상단이 아님Type=공지, Pinned 체크, DatePinned를 체크하고 날짜를 확인. 기존 Pinned 공지가 여러 개인지도 확인
제목이 강조되지 않음Important 체크Important를 체크 후 재동기화. Pinned와 Important는 서로 다른 필드
Changes가 모두 ‘개선’으로 표시됨각 줄 맨 앞 태그[New]/[Improved]/[Fixed] 또는 [신규]/[개선]/[수정]으로 정확히 수정
본문이 비어 있음내용을 DB 속성이 아닌 페이지 본문에 작성했는지행을 페이지로 열어 속성 아래 본문에 작성하고 다시 동기화
이미지가 처음엔 보이다 깨짐Notion 직접 업로드 파일인지외부 이미지 호스팅의 공개 HTTPS URL로 교체
수정 전 내용이 계속 보임Actions 완료 시각, 사이트 동기화 시각Actions 완료 후 사이트 상단 새로고침 버튼 클릭 또는 탭 재진입
공유 링크가 글을 열지 못함Published 여부, URL의 #post 값게시 반영 완료 후 상세 모달의 공유 버튼으로 링크를 다시 복사
🔎
가장 빠른 진단 순서: ① Published 확인 → ② Title/Type/Date 확인 → ③ Actions 최근 실행이 초록색인지 확인 → ④ 사이트 동기화 버튼 클릭 → ⑤ 목록과 상세 모달 재확인.
Final Checklist

게시 전·후 최종 체크리스트

급한 게시일수록 순서를 생략하지 마세요. 긴급 공지는 일반 항목에 Pinned·Important와 수동 동기화 확인을 추가합니다.

게시 전

  • Title이 짧고 구체적인가
  • Type이 올바른 사이트 영역을 가리키는가
  • Date가 실제 공개일과 일치하는가
  • Summary만 읽어도 핵심을 이해할 수 있는가
  • 본문 헤딩·목록·링크·이미지를 검수했는가
  • 업데이트라면 Changes가 한 줄 한 항목인가
  • 긴급 공지라면 Pinned + Important를 체크했는가
  • 모든 검수가 끝날 때까지 Published가 꺼져 있었는가

게시 후

  • Actions 동기화가 성공했는가
  • 글이 올바른 섹션과 순서에 나타나는가
  • 목록의 제목·요약·날짜가 정상인가
  • 상세 모달 본문과 토글이 정상인가
  • 이미지와 외부 링크가 새 창에서도 열리는가
  • Changes 종류와 문구가 올바른가
  • 공유 링크가 해당 글을 바로 여는가
  • 모바일 화면에서도 읽기 편한가
✓
완료 기준: Notion에서 작성이 끝난 것이 아니라, 실제 사이트의 목록·상세·공유 링크를 확인했을 때 게시가 완료된 것입니다.
