📂 중요 파일 역할
dev.html vs index.html
dev.html이 Vite 진입점. npm run build 시 dist/dev.html → index.html로 복사되어 GitHub Pages 배포 파일이 됨. 루트 index.html은 직접 수정하지 말 것.
notion-content.json
Actions가 생성. 같은 출처 정적 파일이라 CORS 없이 항상 성공. 수동 편집 금지, Actions가 덮어씀.
tools.ts / toolGuides.ts
툴 카드 짧은 설명 vs 모달 상세 가이드 분리. 카드 스캔성, 모달은 모델 매트릭스·옵션 상세. Notion의 Tool 속성이 있으면 Notion 글로 대체됨.
notion-worker/
방법 B용. 현재는 미사용, 필요 시 wrangler deploy로 배포.
💡 로컬 이미지 전략: 스튜디오 랜딩에 대표 이미지가 없는 툴(turn, flexboard 등 6종)은 assets/img/tools/에 자체 커버를 둬서 dev.html과 GitHub Pages(/XCONDA_info/) 모두에서 상대 경로로 동작.

// 1. GitHub Actions 러너 (Node 20, CORS 없음)
POST https://www.notion.so/api/v3/loadPageChunk
  body: { pageId: "3e72ebc0-..." } → blockMap 수집 (최대 12 청크)
POST https://www.notion.so/api/v3/queryCollection
  body: { collectionId, viewId, loader: { reducer, limit: 300 } }
  → blockIds + recordMap

// 2. 각 행을 평면 객체로 디코딩
rowToObject(block, schema) → { Title, Type, Published, Date, ... }
isPublished() 필터 → Published=true만 유지
loadBlockMap(row.id) → 각 글 본문 블록 미리 수집

// 3. 스냅샷 JSON 생성 & 커밋
{
  generatedAt, source: { pageId, collectionViewId, collectionId },
  rows: [ { id, Title, Type, ... }, ... ],
  pages: { [rowId]: { blockId: { value: slimBlock } } }
}
→ notion-content.json (용량 최적화: slimBlock으로 crdt_data 제거)

// 4. 브라우저 (src/notionPublic.ts)

Method A

방법 A: 공개 스냅샷 (현재 운영 중)

  1. Notion 페이지 게시 확인
    XCONDA_NEWs 페이지 우측 상단 공유 → 게시(Publish) 켜져 있는지 확인. 현재 ID: 3e72ebc017ad8024a3f5ef8fb9f8c6dd
  2. GitHub Variables 설정 (선택)
    Settings → Secrets and variables → Variables에 NOTION_PAGE_ID, NOTION_DATABASE_ID 설정. 비어 있으면 기본값 사용. 다른 공개 페이지로 바꾸려면 이 변수 변경 후 Actions 실행.
  3. 수동 동기화
    Actions → "Notion 동기화" → Run workflow 클릭 시 즉시 notion-content.json 갱신. 10분 cron 외 긴급 반영 시 사용.
  4. 로컬 테스트
    node scripts/notion-snapshot.mjs --out notion-content.json --print
# --print: rows를 pretty JSON으로 콘솔 출력
# --out: 출력 경로 지정 (기본 notion-content.json)
⚠️ 동기화 실패 시 확인 순서: 1) Actions 최근 실행 성공 여부 (로그 확인) 2) notion-content.json 존재 및 generatedAt 최신 여부 3) Notion 페이지 웹에 게시 상태 유지 여부 4) 게시 해제 시 스냅샷 생성 실패함.
Method B

방법 B: Worker 프록시 (비공개 DB용)

비공개 운영·즉시 반영이 필요할 때 사용. 현재는 미사용이지만 코드는 유지됨.

  1. Notion 통합 만들기
    https://www.notion.so/my-integrations → 새 통합 (Internal) → 권한: 콘텐츠 읽기만 → 시크릿 토큰 복사 (secret_xxx / ntn_xxx)
  2. DB에 통합 연결
    데이터베이스 페이지 우측 상단 ··· → 연결(Connections) → 방금 만든 통합 추가. DB URL에서 32자리 ID 복사.
  3. Worker 배포
    npm i -g wrangler
cd notion-worker
wrangler init xconda-notion --yes
# 생성된 src/index.js를 worker.js 내용으로 교체
wrangler secret put NOTION_TOKEN      # 시크릿 붙여넣기
wrangler secret put NOTION_DB_ID      # DB ID 붙여넣기
wrangler deploy
# → https://xconda-notion.<계정>.workers.dev 주소 복사
  4. 사이트에 연결
    # .env
VITE_NOTION_ENDPOINT=https://xconda-notion.<계정>.workers.dev

# 또는 빌드 없이 테스트:
https://.../XCONDA_info/?notion=https://xconda-notion.<계정>.workers.dev
# 해제: ?notion=off

Single File Build 전략

vite-plugin-singlefile이 모든 JS/CSS를 index.html에 인라인으로 포함. GitHub Pages에서 /XCONDA_info/ 하위 경로일 때도 상대 경로 문제 없이 동작. 외부 에셋은 assets/img/tools/ 6종만 유지 (상대 경로).

# package.json scripts
"dev": "vite"  # dev.html로 개발
"build": "vite build"  # dist/dev.html 생성
"postbuild": "node -e \"fs.copyFileSync('dist/dev.html','index.html')\""
# → index.html이 GitHub Pages 배포 파일이 됨 (558KB+)
"preview": "vite preview"
Deploy

배포 (GitHub Pages)

  1. main 브랜치 푸시 → 자동 배포
    GitHub Pages는 main의 index.html을 서빙. Settings → Pages → Source: Deploy from a branch, Branch: main / root
  2. 빌드 파일 갱신 필요
    npm run build
git add index.html notion-content.json
git commit -m "chore: build & sync"
git push origin main
  3. 도메인
    현재: https://hanahchafilmaker.github.io/XCONDA_info/ · 커스텀 도메인 설정 시 CNAME 파일 추가 필요
⚠️ 주의: index.html은 빌드 결과물 (558KB). 직접 편집하지 말고 dev.html과 src/를 수정한 뒤 npm run build로 재생성하세요. .gitignore에 dist/는 제외되지만 index.html은 포함됨.
CI/CD

GitHub Actions

.github/workflows/notion-sync.yml 
name: Notion 동기화
on:
  schedule:
    - cron: "*/10 * * * *"  # 10분마다 (GitHub 사정으로 지연 가능)
  workflow_dispatch:  # 수동 실행 버튼
  push:
    branches: [main, "arena/**"]
    paths: [scripts/notion-snapshot.mjs, .github/workflows/notion-sync.yml]

concurrency:
  group: notion-sync-${{ github.ref }}
  cancel-in-progress: true

permissions:
  contents: write  # notion-content.json 커밋을 위해 필요

jobs:
  snapshot:
    runs-on: ubuntu-latest
    steps:
      - checkout@v4
      - setup-node@v4 (node 20)
      - run: node scripts/notion-snapshot.mjs --out notion-content.json
        env:
          NOTION_PAGE_ID: ${{ vars.NOTION_PAGE_ID }}
          NOTION_DATABASE_ID: ${{ vars.NOTION_DATABASE_ID }}
      - upload-artifact (7일 보관)
      - commit: notion-content.json 변경 시 자동 커밋
        message: "chore: Notion 콘텐츠 동기화 [skip ci]"
        rebase -X theirs 전략으로 충돌 해결
💡 Variables 설정: Settings → Secrets and variables → Variables에 NOTION_PAGE_ID, NOTION_DATABASE_ID 등록. Secrets가 아닌 Variables인 이유: ID는 민감정보 아님. 토큰이 필요한 방법 B는 Worker secrets로 관리.
✅ 멱등성: 변경사항 없으면 커밋 생략. [skip ci]로 무한 루프 방지. pull --rebase -X theirs로 동시 푸시 경합 시 최신 스냅샷 우선.

Static Content

정적 콘텐츠 코드 (툴 가이드)

Notion에 글이 없을 때 표시되는 폴백. 코드로 관리되는 툴 가이드는 Notion의 Tool 속성으로 오버라이드 가능.

src/content/tools.ts
BASE_TOOLS 19개 정의. 각 툴: slug, name, group, tagline, desc, href, image, badge, steps, tips. TOOL_GROUPS 6개. toolToEntry()로 Entry 변환, getToolGuide()로 상세 가이드 병합, getToolVideo()로 영상 임베드.
const BASE_TOOLS: Tool[] = [
  { slug: "turn", group: "핵심 스튜디오", ... },
  { slug: "flexboard", ... },
  // ... 19개
]
src/content/toolGuides.ts
TOOL_GUIDES: slug → { ko, en } → Block[] . Block 타입: p, h2, h3, ul, ol, callout, toggle, img, video 등. Notion이 없을 때 ArticleModal에 표시되는 상세 매뉴얼.
export const TOOL_GUIDES = {
  turn: { ko: [ { type: "p", text: "..." }, ... ], en: [...] },
  "directors-cut": { ... },
  ...
}
💡 오버라이드 규칙: Notion DB에 Tool 속성이 "Director's Cut"인 글이 있으면, 해당 툴 카드 클릭 시 코드의 toolGuides 대신 Notion 글 본문이 표시됨. 공지/가이드 운영자가 툴 사용법을 직접 수정할 수 있게 하는 기능.
Internationalization

다국어 (i18n) 시스템

UI 다국어: src/i18n/dict.ts
DICT 객체에 300+ 키. ko/en 두 언어. translate(key, lang)으로 조회. TYPE_LABELS, GROUP_LABELS, CATEGORY_LABELS, CHANGE_LABELS로 필터 라벨 번역.
"nav.tools": { ko: "툴 가이드", en: "Tool Guide" }
"toolentry.howTo": { ko: "사용 방법", en: "How to use" }

translate("nav.tools", "ko") → "툴 가이드"
groupLabel("핵심 스튜디오", "en") → "Core Studios"
콘텐츠 다국어
정적 툴: tools.en.ts에 영문 번역, localizeTool()로 병합
Notion: Title EN, Summary EN, Category EN, Changes EN 속성. 있으면 EN 모드에서 해당 필드 대체, 없으면 KO 원문 표시
본문: Notion 본문은 번역 없이 원문 그대로 (작성자가 한/영 모두 작성하거나 KO 위주)

언어 감지: localStorage + 브라우저 언어. LanguageProvider가 setCurrentLang()으로 전역 동기화, formatDate()가 lang에 따라 날짜 포맷 변경

Security

보안 & 권한

🔑 토큰 관리
  • 방법 A는 토큰 없음: 공개 페이지라 토큰 노출 위험 없음. 가장 안전.
  • 방법 B 토큰은 Worker secret: wrangler secret put으로 암호화 저장. 코드/로그에 노출 안 됨. 절대 .env에 커밋 금지.
  • GitHub Variables vs Secrets: Page ID는 Variables (민감 아님), Token은 Secrets (민감). 현재는 Variables만 사용 중.
🛡️ CORS & 공개 범위
  • 스냅샷 방식: 같은 출처 JSON이라 CORS 불필요. 외부 API 의존성 0.
  • Worker 방식: ALLOW_ORIGIN으로 허용 도메인 제한 가능. 기본 "*" → 특정 도메인으로 변경 권장.
  • Notion 공개 페이지: 링크를 아는 사람은 누구나 열람 가능. 민감 정보는 비공개 DB + Worker 방식 사용.
⚠️ 절대 커밋하면 안 되는 것: NOTION_TOKEN, .env, .git/config, wrangler.toml에 토큰 평문. .gitignore에 .env는 이미 제외됨. 토큰은 항상 secret put으로 관리.
Operations

운영 체크리스트

📅 일일 체크
  • GitHub Pages 정상 접속 (https://.../XCONDA_info/)
  • Actions → Notion 동기화 최근 실행 초록불 확인
  • notion-content.json generatedAt 1시간 이내인지
  • 긴급 공지 Pinned 처리 필요 여부
📅 주간/월간 체크
  • Notion DB 속성 정리 (불필요한 태그, 카테고리)
  • 이미지 만료 체크 (1시간 지난 Notion 파일 URL 교체)
  • 툴 가이드 최신화 (tools.ts, toolGuides.ts vs 실제 스튜디오 기능)
  • 번역 누락 체크 (Title EN, Summary EN)
  • npm audit / 의존성 업데이트
🚀 신규 관리자 온보딩 순서
  1. 리포지토리 클론 & npm install & npm run dev로 로컬 실행 확인
  2. NOTION_SETUP.md 정독 (방법 A/B 이해)
  3. Notion XCONDA_NEWs 페이지 접근 권한 요청 & DB 구조 파악
  4. GitHub Variables (NOTION_PAGE_ID) 위치 확인
  5. Actions → Run workflow로 수동 동기화 테스트
  6. 테스트 글 작성 (Type=공지, Published 체크) → 10분 후 사이트 반영 확인
  7. 이 관리자 가이드 북마크 & 운영 체크리스트 숙지
